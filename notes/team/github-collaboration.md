# 在 GitHub 查看小组任务进展

GitHub 可以把任务、代码和验收记录放到同一个地方。成员更新 Issue、推送提交或打开 PR 后，其他人刷新仓库就能看到。它不会自动知道谁在电脑上做了多少工作，也不能根据提交次数认定任务已完成。

## 组员只需要做什么

1. 在仓库的 **Issues** 打开自己的任务。没有任务时，点 **New issue**，选择「小组任务与验收」，填负责人、接收人和要交的结果。新模板随本次 PR 提供，合入默认分支后才会出现在 New issue 菜单。
2. 开始做时，把 Issue 的「当前状态」改成「进行中」。不用写代码也能在网页里编辑 Issue。
3. 有成果时，在同一 Issue 贴文件、PR 或证据链接，写清实际完成了什么。调研、文档、测试同样可以这样交件。
4. 交给接收人时改成「待复核」。复核人留下结果后，再改成「已验收」并关闭 Issue。
5. 卡住时写「阻塞」，说明缺什么、影响哪一步和需要谁协助。拿不到的资料保留待核，不编造完成情况。

| 状态 | 表示什么 | 谁更新 |
|---|---|---|
| 待开始 | 已明确任务，尚未开始 | 负责人 |
| 进行中 | 正在做，尚未交齐 | 负责人 |
| 待复核 | 成果和证据已交，等接收人检查 | 负责人 |
| 已验收 | 接收人确认达到约定要求 | 复核人 |
| 阻塞 | 缺少输入、权限或决定，影响下一步 | 负责人 |

## 怎样看整个小组

- **Issues** 看每个交件的当前状态、负责人、阻塞和复核记录。按 Assignee 筛选可看某位成员的任务；只有把成员实际 GitHub 账号加为 Assignee 后，这个筛选才有效。
- **Pull requests** 看哪些代码正在交付、改了哪些文件、验证了什么、谁已审核。开发分支不会自动合入 main。
- **Commits** 看代码提交记录。它不包含尚未推送的本机工作，也不覆盖成员在仓库以外做的调研和沟通。
- 如果团队后续需要拖动式看板，可在仓库的 **Projects** 建一个 Board，把已有 Issues 加进去，并按上述状态分列。看板的进展取决于 Issue／项目状态更新，不能只因有一次 commit 就自动判定验收通过。
