## 一、业务说明（Business Context）

### 1. 谁在咨询或投诉？

目标用户是外卖配送出现延误、希望了解订单状态或补偿权益的消费者。咨询涉及订单当前状态、预计送达时间、实际完成时间，以及订单是否享有特定配送保障。

典型问题包括：
- “我的外卖已经迟到了，为什么还没到？”
- “这笔订单能获得多少补偿？”
- “为什么别人有赔付，我没有？”

### 2. 用户在哪一步遇到困难？

研究发现，不同平台及保障版本采用不同的补偿条件：
- **美团准时宝**区分普通保障和会员增强权益；
- **京东**的超时免单限定具有指定标识的订单；
- **淘宝闪购**的慢必赔则涉及商家赠送或用户购买的保障服务。

因此，用户可能不清楚自己是否享有保障、哪一个送达时间用于计算延误、补偿是红包、余额还是原路退款。

> **核心业务问题**：用户需要根据具体订单理解自身权益，而不是只得到笼统的“配送超时可以申请补偿”回答。

### 3. 自然语言理解可以提供什么帮助？

拟议 Agent 可以根据用户的自然语言投诉：
- 识别配送延误及补偿咨询意图；
- 引导用户选择订单，保留对话上下文；
- 根据订单对应的保障版本解释适用条件；
- 将复杂条款转换为容易理解的说明；
- 在信息不足或存在争议时整理问题并交接人工。

Agent 的商业价值在于整合订单信息与保障规则、减少重复咨询，并提高服务解释的一致性。

### 4. 哪些决定不应由 Agent 独立作出？

- **订单事实**：订单状态、承诺或预计最晚送达时间、实际完成时间和权益标识，应以订单记录为依据。
- **程序判断**：延误时长、是否达到门槛，以及补偿档位，应按适用规则计算，不由 Agent 自行决定。
- **人工决策**：订单争议、政策例外及本组 Demo 中需要审批的补偿方案，交由人工确认。

## 三、三条可直接用于小组的业务要点

1. **要点 1：先确认订单权益，再判断是否符合补偿条件。**
   仅知道“外卖晚到了”不足以得出赔付结论。不同平台的保障可能要求指定订单标识、会员权益或商家赠送资格。
2. **要点 2：不同保障必须使用对应的时间基准和赔付方式。**
   美团使用对应保障版本的承诺时间与档位；京东明确使用预计最晚送达时间，且晚 20 分钟包含边界；淘宝闪购须区分承诺时间与通用协议中的预计时间。补偿也可能分别为余额、红包或退款。
3. **要点 3：Agent 负责解释，订单事实与正式补偿决定保持独立。**
   Agent 可以识别投诉、整理订单与规则、解释补偿资格。延误计算以订单事实和规则为准；本组 Demo 中的补偿审批由人工完成。这样能将智能客服的业务价值集中在减少重复解释和提高服务一致性上。
